Generate a topology with AI

Describe the lab you want in plain English. HERD's AI reads your actual inventory, proposes a wiring plan, and shows it as a preview you approve before anything is created. You're always the one who commits.

The headline

This is a shortcut, not magic. The AI only ever proposes devices you can already see, you review every node before it's real, and you pick the reservation times yourself. Nothing happens without your click.

First things first

Do you even have this feature?

AI generation is opt-in per deployment. Open the topology editor and look at the toolbar:

You see a Use AI button

Great — it's enabled. Carry on.

No Use AI button

It's turned off on this deployment. Nothing you can do as a user — ask your admin if it should be on.

Which model answers is a deployment choice. Some HERD installs use a hosted model; others run a local or self-hosted one. The flow below is identical either way — you describe, it proposes, you commit.

Asking for what you want

Writing the prompt

Click Use AI. You get a prompt box and an optional file picker.

  1. The prompt. Describe the lab. Name counts ("a pair of firewalls") and exact template names if you know them — the AI is forbidden from inventing templates.
  2. Reference files (optional). Attach a design PDF, a config snippet, or a test plan instead of pasting walls of text. They're treated as context, not commands.
  3. Generate. The AI reads your inventory, drafts a plan, and resolves it against real device ids. A few seconds of loading, then the preview appears.

Trust, but verify

Reviewing the proposal

The plan renders as ghost nodes — dashed, semi-transparent, tagged PROPOSED. A proposal bar floats above the canvas with the summary. Nothing is saved yet.

  1. Ghost nodes. The proposed devices, resolved to real inventory. Dashed border + "PROPOSED" tag = preview only.
  2. The proposal bar. Shows the purpose, device count, link count, and your three choices.

Your call

Accept · Modify · Reject

Accept

Commits the ghosts as real nodes and opens the commit dialog to create the reservation.

Modify

Commits the ghosts as real nodes, then steps back so you can edit freely before saving.

Reject

Throws the proposal away. Nothing is saved. Tweak your prompt and try again.

Making it real

The commit dialog

Accept opens this. It's where you set the reservation window — the AI never picks times.

  1. Start & end. Date-time pickers, defaulting to now + 1 hour and now + 5 hours. Change them to whatever window you actually need.
  2. Apply device configs. This purple box only appears if the proposal carried suggested configs (VLAN / IP / hostname / description). Leave the checkbox off if you don't want them pushed.
  3. Commit. Creates the topology and the reservation in one go, then drops you on the new topology's page.
"Apply device configs" needs admin rights

Pushing configs to devices is an admin-only action. If you're a regular user and tick it, the topology and reservation still get created — only the config push fails (you'll see it in the toast). Leave it off unless you're an admin.

Getting better results

Prompt tips

  • State counts explicitly — "a pair of firewalls," "three test servers." The AI won't propose more of a template than you actually have.
  • Name templates if you know them. The AI is forbidden from inventing template names, so pointing at real ones avoids surprises.
  • Mention VLANs / IPs if you want them. Say it and the AI adds config entries (within an allowlist of vlan / ip / hostname / description).
  • Attach documents for complex topologies instead of cramming everything into the prompt.
It said "inventory shifted" or refused with "no templates"
  • "Inventory shifted during generation" (409): a device became unavailable between the proposal and the commit. Just regenerate.
  • "No templates available": your account has no device visibility, so the AI has nothing to propose. Same permissions fix as first boot.
