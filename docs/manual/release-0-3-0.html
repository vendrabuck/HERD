Release 0.3.0

The version this manual documents. 0.3.0 plugs HERD into the company directory, gives a reservation's fork a usable version history, lets the canvas model infrastructure that is not a device, and hardens the reconcile and production paths underneath.

Some of the things you might expect to find are not missing by accident. The Known boundaries section below lists what 0.3.0 deliberately does not do yet. Check it first.

The short version

What 0.3.0 is

0.2.0 finished the wiring-convergence story. 0.3.0 widens the platform around it: accounts and group membership can now mirror your LDAP or Active Directory, the live-editing fork gets preview, diff, and restore across its version history, and the topology canvas gains network element objects and true multi-port wiring. The reconcile pipeline closes the last stale-connection edge cases it had left.

Under the floor, production deployments keep their JetStream stream data across container recreates, and every service image now installs exactly what uv.lock pins, checked in CI against the lock itself.

The contents

What shipped

01

LDAP directory group sync

ADR 0011, end to end: directory groups map to HERD groups, one to one. Sync now or on an interval, review each run's counts and per-item skips, and let a deactivation and reactivation sweep retire users the directory no longer lists, all on the new Administration → LDAP Sync page. LDAP sync →

02

Fork version preview, diff, and restore

The live-editing history panel grows three verbs: preview any saved version read-only, diff two versions or a version against the current draft, and restore a version to the draft for the next Commit. Restore stages; it never reconciles by itself. Live editing →

03

Network element objects

A non-device canvas node (VLAN segment, Subnet, External cloud, Patch trunk) that many device ports attach to, saved with the topology and validated on fork save. Model the shared segment once instead of faking it as a device mesh. Network elements →

04

Multi-port wiring

The canvas wiring dialog and the admin multi-connect dialog stage many lines between two devices in one pass, with per-line L1/L2/L3 and Connect 1:1 in order, including same-device (loopback) pairing. Wiring → Cabling →

05

Stale wiring that cannot linger

More failure paths that cannot eat wiring: a stale connection left by an ended reservation can no longer strand a VLAN allocation or dodge a rebuild. Leftover rows settle against frozen wiring, and both retry channels revalidate intent before driving anything.

06

Production durability

Under make prod, JetStream stream data now survives container recreates on a mounted volume, and every service image installs exactly what uv.lock pins, so a built image can never drift from the lockfile unnoticed.

Also in this release

  • Inventory table: a Rows per page selector (25, 50, 100, 200) that is remembered across sessions.
  • Deleting a device that any reservation still holds is refused with device_in_use; deleting a secret that a hypervisor references is refused with secret_in_use.
  • The Hypervisors page shows an amber "Deleted secret <id>" marker when a hypervisor's secret has been removed.
  • GET /api/ai/status reports degraded: true with a reason when the AI provider is configured but cannot be constructed, so "no Use AI button" now has two explanations.
  • A seeded end-to-end pass in the release gate that fails on any unexpected skip, which is how the inventory Next-click bug below was found.
  • Fixed: clicking Next on the inventory page right after it loaded could snap back to page 1.

The architecture is unchanged from 0.1.0: twelve FastAPI services behind Traefik, one PostgreSQL schema and migration chain per service, NATS JetStream with transactional outboxes for events. The 0.1.0 architecture section still describes it.

What it was tested against

Quality bar

Measured at the tagged commit by the full make everything run:

  • 4,498 backend unit tests across the 13 suites plus the repo-root suite; backend line coverage 97.1% with every service at 94% or higher.
  • 1,211 frontend tests via vitest, 89.7% line coverage.
  • 12 OpenAPI contract snapshot suites.
  • 192 cross-service integration tests (182 run, 10 gated on LDAP mode or an AI provider).
  • 163 end-to-end browser tests, run twice: 124 on the unseeded stack and 159 again on the seeded stack with no unexpected skip allowed.
  • 41 live-LDAP tests against the checked-in infra/ldap-test directory, hard-required in the gate.
  • Load: 20 simulated users for one minute, 691 requests, 0 failures, median 14 ms, p95 240 ms.

The release gate is unchanged: a clean full validation run (lint, format check, every unit suite with coverage, frontend build, contract snapshots, integration, end-to-end, and load, against a rebuilt ephemeral stack) at the tagged commit, plus the same branch-protection ruleset on main described on the 0.1.0 page. The ruleset also covers release/* branches.

The honest part

Known boundaries

These are limits of 0.3.0, not bugs. If you hit one, the answer is "not yet", not "file a ticket".

  • Network element provisioning (anchored VLANs) is a later phase. Elements are canvas objects today: they attach, save, validate, and diff, but nothing is provisioned from them.
  • Manual wiring retry is not exposed through the external API. The /api/v1 wiring-status passthrough is deliberately read-only; retrying a failed connection is an interactive, owner-gated action.
  • A failed VLAN removal is logged, not blocked on. If delete_vlan fails on last-free, the allocation is already released and the empty definition lingers on the switch until an operator removes it. Bounded lingering is the accepted trade.
  • AI recipe authoring is dark by default. Unchanged from 0.1.0: it stays behind AI_RECIPE_AUTHORING_ENABLED.
  • Driver packages are trusted code. Unchanged from 0.1.0: POSIX setrlimit caps and a subprocess boundary are resource bounding, not OS-level isolation.

Some manual pages describe screens that only appear when a feature is configured, for example the AI Assistant tab, the Use AI button, and the LDAP Sync page's actions. On an install where the feature is off, those surfaces are hidden or inactive. That is the feature gate, not a broken deployment.
