Release 0.7.0

The version this manual documents. 0.7.0 is a hardening release that also gives every account a profile and gives the list pages a left filter panel. A service refuses to start on a blank or unusable token key, template password defaults are masked from non-admins, and a stack on a shared host no longer reads another stack's containers. The Topologies and Reservations lists search and filter, the Topologies list sorts and deletes several rows at once, dialogs open centred, and toasts appear at the bottom centre.

The short version

What 0.7.0 is

0.6.0 was about the two screens you live in. 0.7.0 is a hardening release: most of its 177 changelog entries fix behaviour you never see, and two of them address security advisories. The visible part is smaller and worth knowing. Every account now has a display name, with an optional contact email and phone number, edited in the Profile section of Settings; the header shows the name instead of the username. The Inventory, Reservations, and Topologies lists share a left filter panel: the Inventory filters moved into it unchanged, the Reservations list can be searched and filtered by Status, Category, and Period, and the Topologies list gains search, an Owner filter, sortable headings, and a multi-select delete.

Under the floor, a service refuses to start when AUTH_SECRET_KEY is blank, still the placeholder, or unusable as an HMAC secret, and names the variable. A stack can be published on one host address, each stack's Traefik sees only its own compose project, and make certs writes a self-signed gateway certificate so a fresh clone is served its own. Reservation edits now follow the rules create follows, a topology or a port cannot be deleted while something depends on it, and an admin can pause a webhook subscription. Modal dialogs open centred, toasts appear at the bottom centre, and the Settings page scrolls again.

The contents

What shipped

01

Accounts have profiles

Every account has a required display name and an optional contact email and phone number. You edit yours in the Profile section of Settings; an admin edits any account from Administration, then Users, with Edit profile. The header shows your name, with your username on hover. Email notifications go to the contact email when one is set. Your profile → Users and profiles →

02

List pages have a filter panel

The Inventory filters moved into a left filter panel with no change in behaviour. The Reservations list can be searched and filtered by Status, Category, and Period, and the choices are saved per user. The Topologies list gains search, an Owner filter, sortable headings, and multi-select delete. The reservations list → The topologies list → The Inventory page →

03

Token settings are checked when a service starts

A blank, placeholder, or unusable AUTH_SECRET_KEY, or an AUTH_ALGORITHM other than HS256, HS384, or HS512, stops the service with a message naming the variable instead of signing tokens with it. Two security advisories are addressed by this release: this check, and the template password masking listed under "Also in this release" below. A service exits at startup →

04

A stack shares its host more safely

HERD_GATEWAY_BIND publishes the gateway on one address. Each stack's Traefik reads only its own compose project, and make up refuses to start while another project holds port 80 or 443. make certs writes a ten-year self-signed gateway certificate, so a fresh clone is served its own instead of Traefik's built-in one. make up is refused → The certificate warning →

05

Reservation edits follow the rules create follows

An edit that races a cancel, release, or auto-complete keeps nothing and answers 409. An edit cannot stretch a reservation past RESERVATION_MAX_DURATION_SECONDS, and a device added to a PENDING reservation is judged by the window conflict check. The provisioning timeout no longer restarts on a purpose edit. The calendar answers 503 to a non-admin when device visibility cannot be verified, instead of showing everyone's bookings. The detail modal → The calendar →

06

Interface fixes

Modal dialogs open centred; Tailwind 4 had pinned them to the top-left corner in every release through 0.6.0. Toasts appear at the bottom centre, where they no longer cover the topology editor's Save button. The Settings page scrolls again.

Also in this release

  • An admin can pause and resume an outbound webhook subscription with PATCH /api/v1/webhooks/{id} and the body {"is_active": false} or {"is_active": true}; a paused subscription receives no event, and nothing is replayed on resume. docs/EXTERNAL_API.md →
  • A hypervisor has a Bookable by device group setting, and its Enabled flag is now enforced: a non-admin sees and books a hypervisor's dynamic templates only through a device group their user groups hold a permission on, and a booking on a disabled hypervisor is refused. Register a hypervisor →
  • A topology cannot be deleted while a PENDING, PENDING_PROVISION, or ACTIVE reservation uses it, and a port cannot be deleted or renamed while a cable names it. The topologies list → Ports →
  • Hardened: non-admin template reads mask password-field defaults the way device reads mask password values; the sandbox child for driver packages starts in Python's isolated mode and puts the package on its path only after its resource limits are set; an uploaded tar archive with an oversized header record is refused at the header block; the e2e Selenium container publishes on 127.0.0.1 only; the config login limits failed attempts and answers 429; webhook destinations must resolve to public addresses; a non-admin reservation owner's execution run list shows only runs on devices they can see.
  • Import dry runs are full rehearsals for devices, templates, and topologies, so the dry-run report matches the committing report row for row. The template export and import carry a hypervisor_name column, and the device export leaves out dynamic-instance devices. Bulk import and export →
  • Wiring and dynamic instances recover from failures that used to strand them: VLAN numbers are unique across everything reachable through the current cabling, the background wiring retry no longer stalls on FAILED rows it will never drive, and an upstream 401 or 403 during an INTERNAL_API_TOKEN rotation is retried instead of recorded as a missing device.
  • Auth boots on a stack upgraded in place before make migrate; a reservation that lands FAILED notifies its owner; the buffered assistant route answers 502 Assistant call failed instead of a plain 500.
  • Developer facing: tokens are signed and verified with PyJWT through one helper (herd_common.jwt_codec.decode_access_token, 10 second leeway); existing Hypervisor recipes must accept instance_ref=None; three developer guides, docs/specs/DEVELOPMENT.md, docs/specs/TESTING.md, and docs/specs/CONVENTIONS.md; a test-effectiveness sweep read every test file and landed its fixes; make everything now runs the ci.yml checks it used to skip.

Upgrade notes. After pulling 0.7.0, recreate Traefik (make up, or docker compose up -d) before anything restarts it: a Traefik container created before 0.7.0 still mounts the deleted infra/traefik/traefik.yml, and restarting it fails with a not a directory mount error. 0.7.0 tracks no gateway certificate: the pull removes the certificate files earlier releases shipped, and make up runs make certs, which issues a new self-signed server-chain.crt for the key already on disk, or a new key and certificate when there is none. Clients that trusted the old chain warn again until they trust the new file. To serve a certificate of your own, put its full chain and key in infra/traefik/certs/ as server-chain.crt and server.key before make up; make certs then leaves both alone. A stack whose AUTH_SECRET_KEY is unset, blank, still the placeholder, or not usable as an HMAC key now refuses to start, naming the variable; if a configuration was saved in the config UI, fix the value there. This release adds migrations (among them auth 0009, inventory 0022 and 0024, and a reservations column, provision_started_at), so run make migrate after pulling.

The architecture is unchanged from 0.1.0: twelve FastAPI services behind Traefik, one PostgreSQL schema and migration chain per service, NATS JetStream with transactional outboxes for events. The 0.1.0 architecture section still describes it.

What it was tested against

Quality bar

Measured at the tagged commit by the full make everything run on 2026-11-08:

  • 9,158 backend unit tests passed across the 13 service suites (7,898) plus the repo-root suite (1,260), with 112 skipped; backend line coverage 97.0% (24,625 statements, 741 missed) with every service at 95% or higher.
  • 2,030 frontend tests via vitest in 166 test files, run a second time under TZ=America/Los_Angeles with the same result; coverage is 94.43% lines, 92.99% statements, 86.15% branches, and 92.28% functions.
  • 12 OpenAPI contract snapshot suites.
  • 271 cross-service integration tests: 259 run in the main pass, 3 model-dependent assistant tests run in their own pass after it, the 6 LDAP-mode tests run in their own phase against the gate stack, and 3 are gated on an AI provider or other stack configuration.
  • 206 end-to-end browser tests, run twice: 148 passed and 58 device-gated skipped on the unseeded stack, and 202 passed again on the seeded stack with no unexpected skip allowed (4 exempt).
  • 41 live-LDAP tests against the checked-in infra/ldap-test directory, hard-required in the gate.
  • 28 driver tests against real FRRouting and Nokia SR Linux nodes in the checked-in lab, run on every pull request and inside the gate.
  • Fifteen Postgres-live suites against the gate database, hard-required, 69 tests in all.
  • Load: 20 simulated users for one minute, 660 requests, 0 failures, median 13 ms, p95 120 ms.

New in the gate this release: make everything runs the ci.yml checks it used to skip, among them uv lock --check, the frontend suite under TZ=America/Los_Angeles, and the package-lock.json sync check (changelog, the Delivery detail entry "make everything runs the ci.yml checks it used to skip"). The release gate is unchanged: a clean full validation run (lint, format check, every unit suite with coverage, frontend build, contract snapshots, integration, end-to-end, and load, against a rebuilt ephemeral stack) at the tagged commit, plus the same branch-protection ruleset on main described on the 0.1.0 page. The ruleset also covers release/* branches.

The honest part

Known boundaries

These are limits of 0.7.0, not bugs. If you hit one, the answer is "not yet", not "file a ticket". None of 0.6.0's boundaries closed in this release; five are new.

  • Network element provisioning (anchored VLANs) is a later phase. Elements are canvas objects today: they attach, save, validate, and diff, but nothing is provisioned from them.
  • Manual wiring retry is not exposed through the external API. The /api/v1 wiring-status passthrough is deliberately read-only; retrying a failed connection is an interactive, owner-gated action.
  • A failed VLAN removal is logged, not blocked on. If delete_vlan fails on last-free, the allocation is already released and the empty definition lingers on the switch until an operator removes it. Bounded lingering is the accepted trade.
  • AI recipe authoring is dark by default. Unchanged from 0.1.0: it stays behind AI_RECIPE_AUTHORING_ENABLED.
  • Driver packages are trusted code. Unchanged from 0.1.0: POSIX setrlimit caps and a subprocess boundary are resource bounding, not OS-level isolation.
  • Purpose classification is off by default. It needs a configured AI provider and AI_PURPOSE_CLASSIFICATION_ENABLED. A suggestion never writes the confirmed category by itself; an owner or an admin does.
  • Config-version history for a device outside your groups answers "Device not found". The same answer as the device page gives. That is the visibility rule catching up, not a missing device.
  • A route that names a virtual router needs a driver that declares it. Only a driver declaring supports_vrf drives one; on any other driver the route is refused as l3_vrf_unsupported and stays visible in the Wiring tab until the intent or the driver changes. The shipped frr_l3 driver declares it.
  • The assistant's web sources are off by default. They stay behind AI_DOCS_WEB_ENABLED and are limited to operator-allowlisted https prefixes; the built-in manual and any configured folders are on.
  • A delete right after a cancel can still precede teardown. Execution tears down a cancelled reservation's wiring asynchronously, so a device delete issued in that window can still be refused as in use for a moment. The delete guard answers 503 when cabling or reservations cannot be asked.
  • Webhook delivery is at-least-once. A crash while a POST is in flight can still deliver the same event again. Receivers should treat an event id they have already seen as a repeat.
  • Classify now can show on a finished reservation that is not yet eligible. A reservation that ended before classification existed and was never swept or backfilled shows the button and answers "This reservation is not ready to be classified." Run Classify history first.
  • The Period column sorts by start time. There is no heading that sorts by end time in the UI; the API accepts sort_by=end_time.
  • The About page's skew check is strong evidence on a clean tagged build and weak on a dirty one. The build string names the commit an image was built from, not its bytes, so two images built from the same dirty tree read as identical.
  • The generated gateway certificate is self-signed. Every client warns until you trust server-chain.crt by hand. macOS 10.15 and later refuse a TLS server certificate valid for more than 825 days even when trusted, so the ten-year certificate still warns there until you issue a shorter one of your own.
  • The phone number on a profile is stored and shown only. Nothing calls or texts it.
  • Pausing a webhook subscription is an API call only. No screen exposes it, and resuming does not replay the events it missed. A delivery already under way when you pause finishes and is recorded.
  • A hypervisor created before 0.7.0 starts admin-only. Until an admin assigns a device group to it, a non-admin sees none of its dynamic templates.
  • Hypervisor recipes written before 0.7.0 must accept instance_ref=None. Ending a reservation now runs a keyed destroy for a dynamic instance whose create never reported a handle, and the recipe is called with no handle.

Some manual pages describe screens that only appear when a feature is configured, for example the AI Assistant tab, the Use AI button, the LDAP Sync page's actions, the Purpose Review queue, and the Classify now button. On an install where the feature is off, those surfaces are hidden or inactive. That is the feature gate, not a broken deployment.
