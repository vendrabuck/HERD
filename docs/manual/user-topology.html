User track · Step 3

Building a topology

The topology editor is a canvas where you draw how your lab is wired: drag devices on, connect them, and HERD checks every link against the real physical cabling. It's the signature feature — and it's less scary than it looks.

What a topology is, in one breath

A saved diagram of which devices are connected to which, at which network layer. You build it once, then hand it to a reservation. Green links mean "this path physically exists." Red links mean "it doesn't — fix it before you reserve."

Getting there

Opening the editor

Click Topology in the nav, then either pick a saved topology or hit New topology. You land on a dotted canvas with a floating palette in the corner and a toolbar across the top.

  1. The equipment palette. Your draggable devices. Covered next.
  2. A device node. One piece of equipment on the canvas. A yellow ring means it's selected.
  3. Edge-layer switch (L1 / L2 / L3). Sets which layer new connections are drawn at, and which layer's edges are highlighted.
  4. Use AI. Describe a lab and let the AI propose the wiring. Only appears if your admin enabled it — see the AI guide.
  5. Reserve Topology. Turns this diagram into a reservation. Disabled while any edge is red.

Your parts bin

The equipment palette

The floating panel in the corner lists every DUT (Management-type device) you can see. Drag it by its title bar; collapse it with the −.

  • Only DUTs appear here. Infrastructure switches (L1/L2/L3) are wired in automatically by the routing system — you never drag them by hand.
  • Already-reserved exclusive devices are shown by default. Flip Show reserved resources off to hide them.
  • Devices already on the canvas disappear from the palette. Delete a node and it comes back.
  • Search matches the device name (a case-insensitive substring match); it does not search field values.
Palette completely empty?

You have no device visibility yet. That's the same permissions gap from first boot — ask an admin to add your user group to a device group, then reload.

Putting gear down

Adding devices

Drag a device card from the palette onto the canvas

It drops in as a node with its name, a small type glyph, and a PHYSICAL or CLOUD badge.

Drag the node to position it

Layout is yours. Positions are saved with the topology, so it reopens exactly as you left it.

Dropping the same device twice does nothing

HERD silently prevents duplicates — one node per device, always.

"Cannot connect PHYSICAL and CLOUD devices"

You tried to draw an edge between a PHYSICAL device and a CLOUD one. Dropping both onto the same canvas is allowed; connecting them is not — the edge is rejected with a toast and not created. Make a separate topology for each type.

Gear that does not exist yet

Dynamic resources on the canvas

A dynamic template is hypervisor-backed: there is no physical device behind it. If your admin has set any up, the palette grows a collapsible Dynamic templates section. Drag a card from it and it lands as a dashed purple placeholder rather than a device node — it stands for instances that will be created when the reservation activates.

  1. Dynamic templates. A collapsible section at the bottom of the palette. It only appears when at least one dynamic template exists; each card wears a DYN chip and drags like any device.
  2. The placeholder node. Dashed purple with a DYNAMIC tag. It has no inventory device behind it, takes no cabling, and is never saved with the topology.
  3. Instances. Edit the count right on the node — one placeholder can stand for up to 50 instances.
  4. Reserve Topology. The count in parentheses is real devices only; placeholders travel separately as dynamic requests, prefilled in the next dialog.

Hit Reserve Topology and the reservation dialog opens with the placeholders already converted into a Dynamic instances block:

  1. A prefilled entry. One row per template from the canvas, count carried over. Rows are editable — swap the template or remove the row.
  2. Count. The number of instances to create from this template.
  3. Add dynamic instance. Add more rows here even if you never touched a placeholder on the canvas.

A reservation can carry at most 50 dynamic instances across all rows. Placeholders don't count against the device total and can't be wired — the instances only exist once the reservation activates.

Wiring it up

Drawing connections

Drag from one device's handle (the little dot on its edge) to another's. The wiring dialog opens: source ports in a column on the left, target ports in a column on the right, an open wiring area between them. Wire any number of port pairs in one session instead of one round trip per connection.

  1. Port columns. A free port is fully selectable; one already used, either earlier in this session or by an existing canvas edge, is grayed and tagged WIRED. A port with a registered physical cable is tagged CABLED (informational, still selectable); an uncabled one is tagged no cable the same way.
  2. Layer. Sets the default for lines you draw next; each drawn line gets its own small L1/L2/L3 pill you can change or delete independently. L2 and L3 are logical overlays; they still need a real physical path underneath to count. The layer is recorded on the canvas as that line's intended layer; provisioning derives L2 membership and L3 routes from the resolved path itself, not from this pill.
  3. Connect 1:1 in order pairs every remaining free port on both sides top to bottom in one click: the fast path for wiring two same-size switches straight across.
  4. Add N connections. Adds every drawn line to the canvas at once. HERD immediately checks each one against the cabling graph and colours it; two or more connections between the same device pair collapse into one bundled edge with a count badge on the canvas.

Quick connect

For a single connection, toggle Quick connect in the toolbar before drawing a line. It opens a compact popover instead: pick one port on each side and a layer, then Connect. Its Open wiring dialog link escalates to the full dialog for the same device pair without losing your place.

The part everyone asks about

Red vs green edges

Every edge gets checked against the real physical cabling. The badge on the edge tells you the verdict. Here's the full vocabulary:

What you seeWhat it meansWhat to do
Green + "N hops"A route exists through the switch infrastructure. N is the hop count.Nothing — you're good.
Red + "no path"No route between the two devices. They're in isolated fabrics, or switches between them are missing from inventory.See callout below.
Red + "uncabled port"One of the chosen ports has no physical cable recorded. Beats the path check.Pick a cabled port, or ask an admin to record the cabling.
No badge yetThe check is still resolving.Wait a beat; it'll settle.
A red edge blocks reservation

The Reserve Topology button is disabled while any edge is red — and the server enforces the same rule, so you can't sneak past it via the API. A red L1 edge usually means no physical cabling connects the two DUTs, or the switches between them aren't in inventory. Both are an admin cabling fix, covered in Cabling things up.

I need a link between two physically isolated labsadvanced

For something like an MPLS tunnel between two sites that share no cabling, add a virtual device representing the tunnel and cable it into both fabrics (in the cabling service). The validator then sees a real path and the edge goes green. This is an admin task.

Keeping your work

Saving & version history

Click Save in the toolbar

The name was set when you created the topology on the list page; the editor never asks for one. Save offers an optional change-description field — leave it blank or say what changed.

Every meaningful save is a new version

Open the History sidebar to see the list (newest first) with author and timestamp. Preview any version read-only; Compare two to see Added / Removed / Modified; Restore to roll back.

Restore is blocked while an active or pending reservation still references the topology. Cancel or wait for it to release, then restore.

When the lab is running

Editing during a reservation

Everything above is about the shared master topology. Once a reservation is ACTIVE, it gets a private fork of that topology, and opening the editor from the reservation (via Edit topology) edits the fork — never the master. Drafts autosave, commits apply to the real hardware, port conflicts get a dialog, and after the reservation ends the fork freezes as the read-only as-built record.

That whole flow is the next step of the track: Live-editing a reservation.

The History sidebar above belongs to standalone topologies. A reservation fork keeps its own version list with the same look, but it's view-only: no preview, no diff, no restore.

Don't start from scratch

Cloning & reusable templates

Once you've wired a lab you like, you don't have to rebuild it next time. Two ways to reuse it:

Clone it

Make a full copy of an existing topology as a fresh, editable starting point. The original is untouched; tweak the copy without fear.

Promote to a template

Mark a topology as a reusable template so it shows up as a named starting point for everyone — the canonical “standard test rig,” ready to clone.

A cloned or template-spawned topology still resolves its devices against live inventory when you open it, so you'll only ever wire gear that actually exists and you can see.

Keyboard & mouse cheat sheet
  • Pan: drag empty canvas
  • Select: click a node · Multi-select: shift-click or drag a box
  • Delete selected: Delete (the editor binds only Delete; Backspace does not delete)
  • Connect: drag from a node handle to another node, opening the wiring dialog; inside it, drag between the two port columns or click a port on each side in turn
  • Zoom: mouse wheel, or the + / − controls in the bottom-left. The mini-map in the bottom-right is view-only.
