Admin track - Setup A

First-day setup

You logged in and everything is empty. That's not a bug — HERD ships with nothing in it, and the order you fill it matters. Follow this chain top to bottom and by the end your users can log in, see gear, and reserve it.

Why nothing works until you do this

A device needs a template. A template needs a driver. A user can't see a device until their user group has permission on the device's group. Skip a link in that chain and the next thing looks broken. Do them in order and each one unblocks the next.

This guide assumes the platform is already installed and the config service has run its first-time bootstrap (the wrench-icon flow or env vars). If services are crash-looping or the login form is greyed out, that's an install problem — finish the fresh-setup / config-service step first, then come back here.

The chain

Step 1 · Upload a driver

A driver is a Python package that teaches HERD how to log into and configure a real piece of hardware. Templates point at drivers, so this comes first. Go to Administration → Drivers and click Upload.

  1. Name. Unique and descriptive — e.g. juniper-fw-mgmt. Templates reference it by this name.
  2. Connection type. The big decision: Management for DUTs you reserve, or Layer 1/2/3 Switch for infrastructure.
  3. The package. A .zip or .tar.gz (≤ 10 MB). Validated on first use.
  4. Upload. Stored locally (or in object storage if configured).

Drivers are reference-counted: you can't delete one while a template points at it. Remove or repoint the template first.

Step 2 · Create a template

A template defines the fields a class of device carries and points at the driver that runs it. Go to Templates → New template.

Pick the template type

device templates describe a class of device and must reference a driver. port templates describe a class of port and have no driver.

For a device template, pick the driver and set exclusive

Exclusive (the default) = one reservation at a time. Turn it off for shared infrastructure that many reservations use at once.

Fill in vendor & model

e.g. Juniper Networks / EX2300. These identity fields also let the AI assistant ground itself in real hardware. Suggest with AI can infer them from the name — review before saving.

Add typed fields, then save

Fields can be string / number / boolean / password / dropdown, with optional defaults. Password fields are masked and excluded from search.

Editing a template later is fine, but a new required field with no default breaks existing devices' validation. Prefer adding optional fields.

Step 3 · Create your devices

Now make the actual equipment. Inventory → Add device, pick a template, fill in the field data. (Full walkthrough with ports and cabling is in Equipment & cabling.)

New devices auto-join the seeded No Pool group so nothing is ever unassigned. You move them into real groups in the next step.

Step 4 · Device groups & user groups

These two are the heart of visibility. A device group collects devices; a user group collects people. You then grant a user group permission on a device group.

  1. The transfer arrows. Shuttle devices between Available and In group.
  2. In group. Adding a device here auto-removes it from No Pool. A device can live in several groups at once.
  3. Save. The group exists; now grant access to it (next step).

User groups are symmetrical: User Groups → New group, add members, save. New registrations auto-join Not Grouped until you move them.

Step 5 · Grant permissions (the unlock)

This is the line that makes everything visible to users. On the device group, attach the user groups that should see it.

The mental model

"Give user group networking access to device group lab-a" means every user in networking can now see and reserve every device in lab-a. Once you save this, tell your users to reload — their empty inventory fills in. That's the moment HERD comes alive.

To take access away, remove the permission from the device group — don't yank the user out of their user group. Admins always see every device regardless of groups.

That's the whole chain

Driver → template → device → group → permission. Users can now reserve. Next, the detailed walkthrough for adding real equipment and recording how it's cabled.
