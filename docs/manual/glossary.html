Glossary

The vocabulary HERD uses, in plain words. When a screen throws a term at you and you nod along pretending to know it — this is where you quietly look it up.

DUTDevice Under Test
A device you reserve and run tests against — a firewall, a server, a traffic generator. In HERD terms these are Management-type devices, and they're the only things you drag onto the topology canvas.
Device
One piece of equipment in HERD. Created from a template, lives in inventory, can be reserved and placed on a canvas. Has ports.
Port
A connection point on a device (e.g. eth1/1). Cables connect one port to another. A port with no cable can't carry a topology link.
Template
A reusable schema that describes a class of device or port: which fields it has, their defaults, and (for devices) which driver runs it. You don't reserve a template — you reserve the devices made from it. Creating templates →
Driver
A Python package that teaches HERD how to log into and configure a real piece of hardware. Templates point at drivers; admins upload them. Uploading drivers →
Connection type
A label on a driver that classifies the device: Management (a DUT), or Layer 1 / 2 / 3 Switch (infrastructure). It decides how the device behaves and which driver methods get called.
Topology
A saved diagram of devices and the connections between them. You build it on the canvas, then a reservation can use it. Building a topology →
Reservation
A time-boxed claim on one or more devices, optionally tied to a topology. Making one is how you say "this gear is mine for this window." Reserving →
Exclusive device
A device only one reservation can hold at a time (DUTs, individual instruments). Its status flips to RESERVED while held. Booking it for an overlapping window fails with a conflict.
Non-exclusive / shared device
Infrastructure that many reservations use at once (shared switches, fabrics). Its status never changes on reserve or release — it's plumbing everyone shares.
L1 / L2 / L3
The network layer of a connection. L1 = physical cabling (gray, dashed). L2 = Ethernet / VLAN (blue, solid). L3 = IP / routing (green, dashed). L2 and L3 are logical overlays that still need a real L1 path underneath.
Pathfinding & hops
HERD checks whether two devices can actually reach each other through the recorded cabling. A valid link shows "N hops" (the number of switches in between); an impossible one shows "no path".
Fabric
A connected cluster of L2 switches and the ports linking them. Used to keep VLAN ids unique within a fabric while letting isolated fabrics reuse the same ids.
Ghost / proposed node
A device the AI has proposed but you haven't committed yet — dashed border, semi-transparent, tagged PROPOSED. Accept to make it real, reject to discard. AI proposals →
Device group
A named collection of devices. Device groups control visibility: non-admin users only see devices in groups their user group has access to.
User group
A named collection of people. You grant a user group access to a device group, and everyone in it can then see and reserve that gear. Groups →
No Pool / Not Grouped
The default landing groups. New devices auto-join No Pool; new users auto-join Not Grouped — so nothing is ever unassigned the moment it's created. You move them into real groups afterward.
Role
What you're allowed to do. user reserves gear; admin manages devices, templates, groups; superadmin additionally promotes/demotes other people.
Provisioning
The automatic backend work that fires when a reservation goes ACTIVE — flipping exclusive devices to reserved, wiring L1 ports, setting up L2 VLANs. You don't trigger it; it just happens.

Still seeing a word that isn't here? It's probably a status badge — the full lifecycle key is in Reserving equipment.
